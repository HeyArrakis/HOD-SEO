# HOD — Permanent Blog Publishing Context

From now onward, the HOD-SEO-Research project is the source of truth for HOD content planning and publishing. The job is to **use** the existing system whenever creating, updating, optimizing, or publishing an article.

Do NOT create another SEO strategy, keyword database, content calendar, or research system — all of that already exists here. Do not recreate research unless explicitly asked.

---

## 1. Existing HOD SEO system

Before working on any blog, use the existing project files. The project already contains: Stages 1–19 research, master keyword database, SERP research, competitor research, semantic clusters, SEO architecture, Education architecture, keyword → URL ownership, internal-linking strategy, content boundaries, semantic gap research, AEO/PAA research, Stage 19 content briefs, the final Blog Calendar, and confirmed HOD business facts. (File map: see CLAUDE.md → "Blog production".)

## 2. Final master calendar

Single source of truth for publishing dates: `FINAL-BLOG-CALENDAR/BLOG_CALENDAR_FINAL.csv`.

When asked to create or publish a blog:
1. Find the requested date/topic in the CSV.
2. Check its content type, primary/secondary keywords, intent, priority, production status, target owner, internal-link targets, seasonal context, notes.
3. Follow the calendar exactly.

Do not create another calendar. Do not move dates unless explicitly instructed. Do not swap a scheduled topic for a higher-volume keyword. The calendar is the execution layer of the SEO architecture.

## 3. SEO playbook

`reference/SEO_PLAYBOOK.md` is a strategic reference — apply its principles, don't copy it.

BUSINESS → SEARCH DEMAND → KEYWORDS → INTENT → CLUSTERS → PAGE ARCHITECTURE → CONTENT → INTERNAL LINKS → AUTHORITY → MEASUREMENT → ITERATION, plus SEO → AEO → GEO → AI VISIBILITY.

The purpose is useful, authoritative, interconnected topical coverage around real business demand — not ranking for one keyword.

## 4. Never write a blog from the keyword alone

Understand first: search intent, searcher situation, SERP composition, competing page types, related questions, PAA, AI Overview, semantic entities, supporting concepts, HOD business relevance, existing HOD content, internal-link opportunities, target page/owner, conversion/commercial role.

KEYWORD → INTENT → SEARCHER NEED → CONTENT JOB → PAGE → INTERNAL LINKS → BUSINESS VALUE

## 5. Existing content check is mandatory

1. Does this topic already exist?
2. Does an existing page already satisfy this intent?
3. Is this keyword already owned by another URL?
4. Could this article cannibalize another HOD page?
5. Should an existing article be updated instead?
6. Should two topics be consolidated?
7. Is the new article genuinely necessary?

Only create an article when the architecture/calendar gives it a legitimate content role.

## 6. Keyword usage

Use the primary keyword naturally; no stuffing. Use secondary keywords and semantic concepts where they genuinely help. Prioritize intent, usefulness, completeness, natural language, semantic coverage and clarity over exact-match repetition. Don't force keywords into headings.

## 7. Search intent

Informational, commercial research, transactional, navigational, mixed. Don't turn an informational query into a sales page; don't turn a transactional/category query into a generic blog if the architecture assigns that intent elsewhere. The SERP is evidence — use existing SERP research.

## 8. AEO / answer-first content

QUESTION → DIRECT ANSWER → EXPLANATION → EVIDENCE/CONTEXT → DETAILS → NEXT ACTION

Don't bury the answer. Use concise answer blocks, comparison tables, charts, lists, steps, definitions, FAQs, checklists, examples when the SERP/searcher need supports them.

## 9. PAA + AI Overview

Use existing PAA/AIO research to understand information needs — don't copy questions blindly. Map them naturally into H2/H3, answer blocks, tables, steps, FAQ. Avoid FAQ duplication. If a new question would materially change the approved structure, **flag it before proceeding**.

## 10. E-E-A-T / trust

Use relevant expertise, first-hand HOD knowledge, transparent business information, credible external sources, evidence, author/entity context, methodology. Never fabricate expertise, certifications, laboratories, manufacturing processes, sourcing, customer numbers, awards, guarantees, industry claims, or HOD services. Unconfirmed business facts → mark as **requiring business confirmation**.

## 11. HOD business facts

Use confirmed facts only. Bespoke jewellery (confirmed):
- typically 2–3 weeks to make
- approximately 6–9 days delivery
- approximately 3–4 weeks total
- depends on the stone selected
- never present as a guarantee — use "typically", "usually", "approximately"

If a calendar row is marked `BUSINESS_FACT_REQUIRED`, do not invent the missing information.

## 12. Internal linking

Use the Stage 16 / Stage 19 internal-linking requirements: Blog → Education, Education → Blog, Blog → Product/Category, Education → Commercial, Hub ↔ Spoke, related article ↔ related article. Natural descriptive anchors. Don't force links, invent URLs, or create new URLs without checking the architecture.

## 13. Topical authority

No isolated articles. Each article relates to a topic cluster, hub, Education page, commercial page, related article, or identified strategic gap. TOPIC → SUPPORTING CONTENT → INTERNAL LINKS → TOPICAL AUTHORITY.

## 14. Content quality — required workflow

BUSINESS CONTEXT → SEARCH DEMAND → INTENT → EXISTING CONTENT CHECK → CONTENT JOB → RESEARCH → ARTICLE → INTERNAL LINKS → SEO/AEO QA → HUMAN REVIEW → PUBLISH → MEASURE → UPDATE

Add something beyond generic AI content: original HOD context, practical guidance, evidence, clear explanations, examples, comparisons, defensible conclusions.

## 15. Default structure

1. Clear title/H1
2. Direct answer / opening value
3. Main explanation
4. Logical H2/H3 sections
5. Supporting evidence/examples
6. Tables/charts/steps where useful
7. HOD-specific context where genuinely relevant
8. Internal links
9. Clear conclusion / next action
10. FAQ only when useful and non-duplicative

No filler sections, no arbitrary word count. Depth matches intent and SERP.

## 16. SEO elements checklist

H1, title, meta description, URL, primary keyword, secondary keywords, semantic entities, heading structure, internal links, image alt text, image relevance, canonical, schema, breadcrumbs, author/entity information. Preserve existing URLs unless an explicit architectural decision says otherwise.

## 17. Images / visuals

Chosen for intent and usefulness: diagrams, comparison charts, jewellery examples, size charts, educational illustrations, process visuals. No decorative padding. Alt text describes the actual image naturally — no stuffing.

## 18. Playbook tactics — use with judgment

Do NOT automatically apply URL refreshing, exact-match domains, clicks/PageRank interpretations, or parasite SEO unless there is a specific HOD reason **and** the user explicitly asks.

Do not automatically apply byte-level/2 MB HTML optimization tactics unless relevant to the task. The Googlebot approximately 2 MB fetch limit is documented by Google; the optimization tactic should be applied selectively.

Default system: crawlability, indexability, useful content, architecture, internal links, authority, entities, intent, AEO, AI visibility.

## 19. SuperSEO skill

Use the SuperSEO skills (`superseo:*` — keyword-deep-dive, content-brief, write-content, improve-content, semantic-gap-analysis, featured-snippet-optimizer, page-audit, eeat-audit, etc.) where applicable rather than inventing a different workflow. Combined context = HOD research + final calendar + playbook + SuperSEO. On conflict, HOD architecture/ownership decisions and the user's explicit instructions win.

## 20. Do not override the HOD architecture

Stages 1–19 contain deliberate decisions on keyword/URL ownership, Education vs Blog, commercial pages, clusters, cannibalization, internal linking and content boundaries. If a new opportunity conflicts: **STOP and flag the conflict.** Never silently change ownership.

## 21. DataForSEO

Use existing research first; don't repeat completed research without a reason. Before any paid call: verify pricing → define exact task configuration → calculate maximum cost → request user approval → run only the approved configuration.

## 22. When the user says "write this blog"

Means: execute the approved calendar item using the complete HOD SEO system.
1. Open `BLOG_CALENDAR_FINAL.csv`.
2. Locate the article.
3. Read its keyword and intent data.
4. Read its content/ownership context.
5. Check the Stage 19 brief if available.
6. Check existing related pages.
7. Check internal-link requirements.
8. Use existing SERP/PAA/AIO research.
9. Use SuperSEO where applicable.
10. Then write.

Don't ask the user to repeat information already in the project.

## 23. Before publishing — final QA

- **Content:** intent satisfied; primary keyword naturally covered; semantic coverage sufficient; no filler; no unsupported claims.
- **SEO:** title, H1, meta description, URL, headings, internal links, schema, images, alt text.
- **AEO:** direct answer; important questions answered; PAA incorporated naturally; answer-friendly structure.
- **HOD:** business facts accurate; brand positioning accurate; no invented claims; correct product/category references.
- **Cannibalization:** no conflict with existing HOD URLs.

Never publish immediately after drafting. Present for human review unless the user explicitly asks for autonomous publishing.

## 24. Measurement after publishing

After sufficient time, use GSC, rankings, impressions, CTR, clicks, engagement/conversion data and AI visibility to decide on content improvement, internal-link improvements, title/meta changes, added semantic coverage, consolidation, or refresh. Publishing ≠ success.

## 25. The most important rule

Don't think "What SEO blog should I write?"

Think: **"What does HOD need to own, what does the searcher need, what does the existing architecture assign to this page, and how can this article satisfy that intent better than the current alternatives?"**

BUSINESS → SEARCH DEMAND → INTENT → ARCHITECTURE → CONTENT → INTERNAL LINKS → AUTHORITY → SEO → AEO → AI VISIBILITY → MEASUREMENT → ITERATION

Use AI to execute this system. Do not replace the system with generic AI content.
